What this is

When a deterministic service breaks you get a stack trace. When an agent breaks you get a confident, well-formatted, silently wrong answer — and the real mistake is usually many steps upstream of the bad output. AgentLens finds that step: a deterministic rule layer for mechanical failures, and an LLM judge that reads the whole trajectory at once looking for a later claim that contradicts an earlier one.

Start here

The result worth looking at

A live run of a separate multi-agent project produced an unplanned contradiction: the Analyst states the 2024 Nobel Prize in Chemistry was awarded for protein-design work; the Critic, reviewing that same report two steps later, states the 2024 Nobel Prizes have not yet been announced. The judge missed it 5 times across two prompt versions. Requiring it to emit an extracted claims array before its verdict — making extraction a visible output rather than an instruction it could skip — fixed it.

In the Trace viewer, scroll to step 15. The contradiction sits on the page as two claims: the green step above says the prize was awarded, the red step says it wasn't.

What this is not

  • Not validated at scale. One real trace. Sample sizes of 1–11 runs per trace. Treat it as an early read, not a number with tight error bars.
  • One known disagreement. On silent_wrong_default the judge reproducibly picks step 1 over the labeled step 3 — a defensible reading, reported rather than quietly excluded.
  • The pre-fix 89% is not reproducible from this repo's data. It counts runs recorded outside the benchmark reports. The Benchmark tab's pre-fix era is tagged partial set for exactly that reason.
Everything here reads files straight off disk — no build step, no API key, no account. It needs a server only because browsers block fetch() on file:// URLs: python3 -m http.server from the project root.

Get started

Seven steps in the order that costs you the least, plus an optional eighth. Steps 1–2 need nothing but Python — the rule layer is deterministic and makes no API call, so you can watch AgentLens catch a real failure before deciding whether to spend a key on it. Everything from step 4 on calls an LLM.

You're already past step 1 if you're reading this — it's served from your own clone.

Clone and install no API key

Three dependencies: the two LLM SDKs and python-dotenv. Python 3.10 or newer.

git clone https://github.com/Shree-2004/agentlens.git
cd agentlens
pip install -r requirements.txt

See it catch something, free no API key

tool_loop.json is a mechanical failure — the same tool called with identical arguments three times. The rule layer finds it with no LLM involved, so this works offline and proves your install is sound.

python3 analyze.py sample_traces/tool_loop.json output/diagnosis.json --no-judge

You should see Critical step: 7 (tool_call_loop, high confidence, via rule).

Serve the pages no API key

Browsers block fetch() on file:// URLs, so the UI needs a server — any static one will do. Run this from the project root and this page lives at http://localhost:8000/.

python3 -m http.server

Nothing is uploaded anywhere. Every page here reads JSON off your disk.

Add an API key key needed

Either provider works — the judge auto-detects whichever is set, checking Anthropic first if both are. Put them in a .env file in the project root (gitignored) or export them.

# pick one
export ANTHROPIC_API_KEY=sk-ant-...
export GOOGLE_API_KEY=...
Gemini's free tier caps at 20 requests/day per project per model. That is the single biggest practical constraint on this project — it is why the benchmark below was run in fragments across many sessions. Anthropic is paid but has no daily cap.

Diagnose a trace with the judge key needed

Now the semantic layer runs: the judge reads the whole trajectory at once, extracts every checkable claim, and compares them against each other looking for a contradiction.

python3 analyze.py sample_traces/stale_plan_tier.json output/diagnosis.json

It should land on step 2 — where a stale cached "free tier" fact enters, three steps before the billing record that contradicts it.

Look at what it found no API key

Open the tab and pick output/diagnosis.json from the dropdown. The timeline turns red at the critical step, amber for everything downstream of it, and the judge's extracted claims sit under the step each came from.

Refresh this page after any new run — the picker only lists diagnosis files that actually exist.

Score the judge yourself key needed

Don't take the numbers on the tab on faith — regenerate them. This runs every labeled trace N times and scores each run against a label written before the judge ever saw it.

python3 run_benchmark.py 3 --output output/benchmark_report_v3.json
10 traces × 3 runs = 30 calls, which does not fit in Gemini's free daily cap. Use --only trace1.json,trace2.json to run a subset, or --provider anthropic to finish in one sitting.

To see a new report in the Benchmark tab, add its filename to output/benchmark_manifest.json under the prompt version it belongs to. That step is deliberate friction: pooling runs from different judge prompts would average away the exact difference a prompt change was made to measure.

Point it at your own agent optional

Traces are plain JSON — a task plus ordered steps — so you can write an adapter for any agent. If yours is already instrumented with Langfuse, there's one built in.

pip install langfuse
export LANGFUSE_PUBLIC_KEY=pk-lf-...
export LANGFUSE_SECRET_KEY=sk-lf-...
python3 analyze.py --langfuse-trace-id <id> output/diagnosis.json
Honest status: the Langfuse adapter is verified against fixtures, not yet against a live Langfuse project. The mapping is self-consistent; whether it matches what a real instance returns is untested.

Checking the tests
