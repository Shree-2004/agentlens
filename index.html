What this is

When a deterministic service breaks you get a stack trace. When an agent breaks you get a confident, well-formatted, silently wrong answer — and the real mistake is usually many steps upstream of the bad output. AgentLens finds that step: a deterministic rule layer for mechanical failures, and an LLM judge that reads the whole trajectory at once looking for a later claim that contradicts an earlier one.

The result worth looking at

A live run of a separate multi-agent project produced an unplanned contradiction: the Analyst states the 2024 Nobel Prize in Chemistry was awarded for protein-design work; the Critic, reviewing that same report two steps later, states the 2024 Nobel Prizes have not yet been announced. The judge missed it 5 times across two prompt versions. Requiring it to emit an extracted claims array before its verdict — making extraction a visible output rather than an instruction it could skip — fixed it.

In the Trace viewer, scroll to step 15. The contradiction sits on the page as two claims: the green step above says the prize was awarded, the red step says it wasn't.

What this is not

  • Not validated at scale. One real trace. Sample sizes of 1–11 runs per trace. Treat it as an early read, not a number with tight error bars.
  • One known disagreement. On silent_wrong_default the judge reproducibly picks step 1 over the labeled step 3 — a defensible reading, reported rather than quietly excluded.
  • The pre-fix 89% is not reproducible from this repo's data. It counts runs recorded outside the benchmark reports. The Benchmark tab's pre-fix era is tagged partial set for exactly that reason.
Everything here reads files straight off disk — no build step, no API key, no account. It needs a server only because browsers block fetch() on file:// URLs: python3 -m http.server from the project root.
